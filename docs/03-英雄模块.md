# 03 — 英雄模块 Hero

[← 返回索引](./README.md)

## 职责

- 英雄定义、战前选择、局内运行时实例
- 每个英雄：**主动技能 + 被动技能**（技能独立文件）
- 流派标签与 **明确取舍**——英雄 alone 不完整，必须靠装备 + 道具补全 build

---

## 平衡设计铁律（已确认）

> **英雄一定要取舍。** 英雄只提供「方向」和「底子」，真正强的 build = 英雄 + 装备 + 道具 + 局内属性选择 组合优化。不能让英雄自带全套能力。

### 原则 1：一条长板，多块短板

每个英雄精通 **一个方向**，其他维度明显偏弱。不能又是叠血、又能回血、又能高输出。

### 原则 2：英雄不给「成套解决方案」

| ❌ 错误示例 | ✅ 正确做法 |
|------------|------------|
| 叠血英雄自带高回血 | 英雄只给 **血量上限** 或 **减伤**；回血来自装备/道具/属性选择 |
| 抓宠英雄攻击力还行 | 抓宠英雄攻击、生存 **明显偏低**，靠宠物和养成补伤害 |
| 挖宝英雄能扛能打 | 挖宝英雄战斗面板弱，靠挖宝产出滚雪球 |

### 原则 3：装备 + 道具是补完拼图

```
最终战力 = 英雄底子（窄） + 装备（6 格） + 道具（叠加） + 局内属性 + 宠物/附魔等
```

玩家选英雄 = 选 **养成路线起点**，不是选「成品」。

### 原则 4：技能也只强化本流派，不越界

- 叠血英雄被动：「最大生命 +15%」✅
- 叠血英雄被动：「最大生命 +15% 且每秒回血 2%」❌（回血应靠装备凑）

### 原则 5：道具可跨流派偷师（英雄不行，道具行）

英雄 **技能与被动** 不越界，但 **道具可以** 把别的流派能力「借」过来：

```
英雄 = 本局长板起点 + 4选1 权重偏置
道具 = 最终身份（可偏离英雄标签）
```

| 英雄 | 仅靠英雄 | 靠道具可变成 |
|------|----------|--------------|
| 抓宠 | 宠物流 | + 坦克（肩章、铁餐盘）/ + 赌狗（假筹码） |
| 挖宝 | 经济事件 | + 输出（狂战士血清、连射武器） |
| 输出 | 脆高攻 | + 续航（共生种子）/ + 浅宠（驯兽项圈） |
| 坦克 | 耐打无回 | + 输出（佣兵合同）/ + 挖宝（周末矿工证） |

实现见 [24 §3.4 archetypeBridge](./24-道具设计.md) — `outsiderOnly` 道具专给 **非本流派** 英雄；本家用 `archetypeFit` 拿正统加成。

## 流派定义（修正版）

| 流派 | 英雄自带（长板） | 英雄刻意偏弱（短板） | 靠装备/道具补什么 |
|------|------------------|----------------------|-------------------|
| **叠血 / 坦克** | 生命上限、减伤、格挡类 | 攻击力、移速、暴击 | 回血装、反伤装、护盾道具 |
| **挖宝** | **幸运值、财富值**（通用）；技能改挖宝事件权重 | 攻击、血量、防御 | 战斗装、保命道具（从宝里挖出来） |
| **抓宠** | **幸运值**（通用）；技能改捕获/合并 | 攻击、生存 | 宠物战力、精灵球、辅助装 |
| **输出** | 攻击、暴击、技能伤害 | 身板脆、无特殊玩法加成 | 吸血装、闪避装、生存道具 |

> **叠血英雄可以「耐打」，但不能「自愈」。** 续航是玩家用装备和道具赌出来的。

---

## 每个英雄必备

| 能力 | 说明 |
|------|------|
| **主动技能** | **必填**。CD / 消耗 / 效果；可战斗或非战斗（挖宝、附魔台内） |
| **被动技能** | **必填**。常驻或条件触发，定义流派长板，不补齐短板 |
| 流派标签 | `tank` / `treasure` / `capture` / `dps` / `gambler` … |
| 抓宠资格 | 仅 `capture` + `canCapture: true` |
| 属性选择池 | 权重偏向本流派 |

> 文档或配置里 **只有被动没有主动** 视为未完成，不可进开发。

## 配置与校验

```
data/configs/heroes/{heroId}.json
data/configs/skills/active/{skillId}.json
data/configs/skills/passive/{skillId}.json
data/configs/heroes/balance-rules.json   # 可选：自动校验英雄是否越界
```

```typescript
HeroConfig {
  id: string
  name: string
  archetype: string
  baseStats: StatBlock
  activeSkillId: string          // 必填，指向 skills/active/
  passiveSkillId: string         // 必填，指向 skills/passive/
  attributePoolId: string
  canCapture?: boolean
  // 设计备注（给策划看，不进战斗逻辑）
  designNotes?: {
    strength: string[]           // 如 ["高生命上限", "减伤"]
    weakness: string[]           // 如 ["无回血", "低攻击"]
    recommendedItems: string[]   // 推荐搭配的道具/装备方向
  }
}
```

### 配置校验建议（开发期）

新增英雄时检查 `baseStats` 与 `passiveSkill` 是否违反流派规则，例如：

- `archetype === 'tank'` 且被动含 `regen` / `lifesteal` → **警告或拒绝入库**
- `archetype === 'capture'` 且 `baseStats.attack` 高于全局中位数 → **警告**
- `baseStats` 含 `captureRate` / `digRare` 等 **非通用 StatId** → **拒绝入库**（见 [25 §2](./25-属性系统设计.md)）
- `activeSkillId` 或 `passiveSkillId` 为空 → **拒绝入库**
