# 25 — 属性系统设计 StatSystem

[← 返回索引](./README.md) | 核心入口：[02-核心系统](./02-核心系统.md)

> **定稿 v1.6** — 全游戏属性枚举、正负含义、影响链路。**设计道具 / 英雄 / 附魔前必读。**

---

## 1. 为什么要有本文档

- 道具条件「生命 ≥ 500 → 移速 +8%」依赖 **maxHp**、**moveSpeed** 有明确定义
- 英雄 `baseStats`、附魔词条、道具 `perStack` 必须 **共用同一套 StatId**
- 每个属性要写清：**正数干什么、负数干什么、影响哪段逻辑**
- **三层分离**：局内英雄面板 ≠ 英雄开局配置 ≠ 道具/附魔 Build 加成

---

## 2. 三层属性模型

> **全环节跟着 ① 的 18 条属性走** — 抓宠、强化、附魔、商店、赌场、挖宝等 **只读这 18 条 + ③ Build**，禁止再发明玩法专用 StatId。  
> **大力出奇迹**：幸运 = 0 但攻击力极高，捕获/强化/附魔照样能成；**叠幸运 + 叠攻击** 更高，是 **并列加成** 不是二选一。  
> **强者红利**：面板强的 build 在资源侧也应更好 — 不能只靠堆幸运。

| ❌ 错误 | ✅ 正确 |
|--------|--------|
| 面板只有 6 条 | 面板 18 条；**全系统读 18 条** |
| 捕获只看 luck | **attack + luck + maxHp** 并列；luck=0 高攻仍高 |
| 商店只看 luck | **luck + attack + wealth**；强者刷得到好货 |
| 大家都堆 luck | **plateau 软饱和** + 多通道；坦克靠 maxHp 线 |
| enhanceSuccess 占主面板 | 收在 ③ Build 折叠区 |

### 2.1 三层对照

| 层级 | 是什么 | 玩家在哪看到 |
|------|--------|--------------|

**生存** `maxHp` · `hpRegen` · `lifeSteal`

**防御** `armor` · `dodge` · `damageReduction`  
**机动** `moveSpeed` · `pickupRange`

见 §6。可填 §2.2 任意字段；**禁止** captureRate / petDamage / enhanceSuccess 等。

### 2.4 ③ Build — 不进主面板

**养成** enhanceSuccess, enchantRareWeight … **宠物** petDamage, maxPetDeploy … **场所** casinoWinRate, auctionSnatchRate …

### 2.5 18 属性全链路 · 联动铁律（已确认）

#### 原则 A：并列叠加，luck = 0 也能玩

每个玩法用 **多条 18 属性并列贡献**，各通道 **软饱和（plateau）**，stat 本身 **无上限**：

```
玩法加成 = Σ linkageLane(stat_i)   // 每条通道独立，递减增量
linkageLane = plateau × (1 - e^(-stat×weight/plateau))
```

- **attack 高、luck = 0** → 仍拿满 attack 那条上限（**大力出奇迹**）  
- **attack 高、luck 也高** → 两条都加，成功率 **更高**（协同，不是二选一）  
- **maxHp 高、luck 高** → 捕获、抗 debuff 等 **可双吃**

#### 原则 B：养成无上限 — **属性值本身不设顶**

| 项 | 规则 |
|----|------|
| 18 条主属性 | **可无限叠**（本局内养成游戏核心）；registry **不设 benefit 上限**，仅引擎安全顶（如 999999） |
| 联动贡献 | 用 **递减增量**（软饱和），不是把 stat 值 cap 住 — stat 越大仍有收益，边际递减 |
| 与战斗 | 攻击/血量/幸运等 **战斗公式直接吃完整 stat**，养成永远有意义 |

#### 原则 C：血量永不为负

| StatId | 下限 | 上限 | 说明 |
|--------|------|------|------|
| **`maxHp`** | **1** | 无 | **不可能为负**；结算后 `maxHp = max(1, 计算值)` |
| 当前 HP | 0 | maxHp | 战斗中可以扣到 0 死亡，但 **maxHp 本身 ≥ 1** |
| 其它 benefit stat | 视 stat 定 | 无 | 如 `attack` 可被诅咒为负；`luck` 建议 floor 0 |

**maxHp 必须进联动** — 坦克/叠血 build 的「强」不能只看 attack（见下表）。

#### 原则 D：多维强度 — 不用 attack 单独定义英雄强弱

> 流派多：输出、坦克、赌狗、抓宠… **每个流派靠不同的 18 属性组合变强**，联动表禁止「全系统 attack 权重最高」。

| 流派 | 主看的 stat | 也应吃到的联动 |
|------|-------------|----------------|
| 输出 | attack, critDamage | 强化、捕获 attack 线、商店 attack 线 |
| **坦克 / 叠血** | **maxHp**, armor | 捕获 hp 线、赌场抗 debuff、挖宝 trap、**强化/附魔 hp 线** |
| 赌狗 | luck, wealth | 商店、掉落、挖宝 |
| 均衡 | 多 stat 中等 | 多通道都有 modest 贡献 |

**禁止**：所有 `stat-linkage` 系统只配 attack + luck，不配 maxHp / armor / wealth 等。

#### 原则 E：幸运单项软饱和必须「够小」

| 约束 | 说明 |
|------|------|
| luck **通道 plateau** | 每系统 luck 通道的软饱和顶 **≤ attack / maxHp 通道** 或同级 |
| 目标 | 纯堆 luck 不能碾压；纯堆 attack **或** 纯堆 maxHp 都是完整 build |

#### 原则 F：强者红利

高 **attack / maxHp / armor** 在 **商店、掉落、强化、附魔** 上须有可见收益，不能只让幸运流独享好资源。

#### 各系统读哪些 ① 属性（+ ③）

| 系统 | 并列通道（示例） | ③ | 要点 |
|------|------------------|---|------|
| 商店传说/极品 | luck, attack, wealth, **maxHp** | — | 四维共同构造 |
| 击杀稀有掉落 | luck, attack, wealth | — | |
| 强化成功 | attack, luck, critRate, **maxHp** | enhanceSuccess | 坦克也有「皮实手稳」线 |
| 附魔好词条 | luck, wealth, attack, **armor** | enchantRareWeight | |
| **捕获** | attack, luck, **maxHp** | — | 攻+运+**血** |
| 挖宝稀有 | luck, wealth, attack | — | |
| 挖宝 trap 惩罚 | **maxHp**, armor | — | 血厚皮硬 |
| 赌场负面 debuff | attack, **maxHp**, luck(小) | — | |
| 回合金币 | wealth, goldGain | — | |
| 拍卖被抢 | armor, wealth, **maxHp** | auctionSnatchRate | |

> **财富值 ≠ 钱包金币。**

### 2.6 三条 build 路

| 路线 | 堆什么 | 玩什么 |
|------|--------|--------|
| **大力 / 输出** | attack, critDamage | 捕获/强化靠攻；商店强者刷新 |
| **坦克 / 血牛** | maxHp, armor | 捕获 hp 线、抗 debuff、减 trap、强化/附魔 **hp/armor 线**、拍卖 |
| **赌狗 / 经济** | luck, wealth | 商店权重高，但战斗弱有代价 |

#### 原则 H：多属性 **共同构造**（2~N 通道，非乘算）

| 模式 | 本游戏 |
|------|--------|
| ❌ 只绑两个 stat | 每个系统在 `stat-linkage.json` 配 **2~N 条通道** |
| ❌ 只用 attack 联动 | 必须含 **maxHp / armor / wealth** 等，按流派有主通道 |
| ❌ 两两乘算 `attack×luck` | **加性多通道**独立求和 |
| ✅ 共同构造 | `总加成 = Σ linkageLane(通道_i)` |

可选扩展：`synergyTerms` — 默认不用。

#### 原则 I：负属性（attack = -100，luck = 100）

**benefit 型联动** — 每条通道：**负 stat → 该通道 0**；**maxHp 永 ≥ 1**，hp 通道永远 ≥ 0：

```typescript
/** 递减增量：stat 无上限，贡献软饱和于 plateau，养成越大仍有边际收益 */
function linkageLane(stat: number, weight: number, plateau: number): number {
  const s = Math.max(0, stat)   // maxHp 已在 StatSystem 保证 ≥1；其它负值通道归零
  return plateau * (1 - Math.exp(-s * weight / plateau))
}

function linkageBonus(channels: LinkageChannel[], stats: Record<StatId, number>): number {
  return sum(channels.map(c => linkageLane(stats[c.statId], c.weight, c.plateau)))
}
```

**范例 · 捕获**（plateau 示意：attack 0.15 / luck 0.12 / maxHp 0.10）：

| attack | maxHp | luck | 谁贡献大 |
|--------|-------|------|----------|
| 200 | 50 | 0 | **attack 线**（输出 build） |
| 30 | **2000** | 0 | **maxHp 线**（坦克 build 照样抓得稳） |
| -100 | 800 | 100 | hp + luck 线；attack 线 = 0 |

要点：

- **luck 高救不了 attack 线** — 负 attack 只是 attack 通道归零  
- **坦克不靠 attack 也能在捕获/抗 debuff 上强** — maxHp/armor 通道同级配置  
- **战斗仍吃真实 stat**（attack 可为负）；**maxHp 永 ≥ 1**

## 3. 计算公式（全局）

```
最终值 = clampPerStat( (基础值 + Σflat) × (1 + Σpercent) × Πmultiply )
```

| 规则 | 说明 |
|------|------|
| **养成无上限** | benefit 型 stat **不设 max**（引擎安全顶除外） |
| **maxHp 下限** | `maxHp = max(1, 算后值)` — **永不为负** |
| 其它 stat | 按 `stat-registry.json` 的 `min`；`attack` 等可为负 |

| Modifier | 写法 | 例 |
|----------|------|-----|
| `flat` | +10 | 最大生命 +100 |
| `percent` | +0.15 或 +15% | 攻击 +15% |
| `multiply` | ×1.2 | 移速 ×1.2（少用，留给技能） |

- **基础值**：英雄 `baseStats` + 武器白值（6 格相加或按武器规则）
- **flat / percent**：道具、附魔、局内 4 选 1、宠物、Buff 等，带来源 `sourceId`
- 计算顺序：**先 flat → 再 percent → 最后 multiply → 再 per-stat clamp（仅 min，maxHp min=1）**

**构造方式**：`channels[]` — 每 channel = StatId + weight + **plateau**（软饱和顶，不是 stat 上限）；**2~N 条**并列求和。

```typescript
type LinkageChannel = { statId: StatId; weight: number; plateau: number }
```

**配置示例 · 捕获（4 通道 — 含 maxHp，不单靠 attack）**：

```json
{
  "systemId": "capture",
  "channels": [
    { "statId": "attack", "weight": 0.02, "plateau": 0.15 },
    { "statId": "luck",   "weight": 0.015, "plateau": 0.12 },
    { "statId": "maxHp",  "weight": 0.0008, "plateau": 0.12 }
  ]
}
```

```typescript
captureMult = 1 + linkageBonus(captureChannels, finalStats)
// maxHp=2000 的坦克：hp 通道接近 plateau，与 attack=200 的输出 build 不同路，都能抓
```

**数值约束**：同系统各通道 **plateau 同级**（如 capture 三条均 ~0.12~0.15）；**禁止**只配 attack+luck 不配 maxHp/armor。

## 4. 属性方向：增益 vs 风险

| 类型 | 说明 | 正数 | 负数 |
|------|------|------|------|
| **增益型** `benefit` | 越大越强 | 加属性 | 削弱该属性 |
| **风险型** `risk` | 越大越坑玩家 | **坏事加重**（被抢、碎装） | **坏事减轻**（稀有） |

```typescript
StatDef {
  id: StatId
  polarity: 'benefit' | 'risk'
  defaultMin?: number
  defaultMax?: number
}
```

UI：增益型 `+10 攻击` 绿色；风险型 `+5% 被抢概率` **红色**。

### 5.2 输出 Combat

| StatId | 中文 | 类型 | 影响什么 | **为正** | **为负** |
|--------|------|------|----------|----------|----------|
| `attack` | 攻击力 | benefit | 武器基础伤害、技能倍率基数 | 打得狠 | 刮痒 |
| `attackSpeed` | 攻击速度% | benefit | 武器冷却 ÷(1+攻速%) | 射得快 | 射得慢 |
| `critRate` | 暴击率% | benefit | 命中 roll 暴击概率 | 暴击多 | 几乎不暴 |
| `critDamage` | 暴击伤害% | benefit | 暴击时伤害 ×(1+暴伤%) | 暴得疼 | 暴了也不疼 |
| `range` | 攻击范围% | benefit | 武器射程 / AOE 半径缩放 | 手长 | 贴脸才打到 |
| `pierce` | 穿透 | benefit | 直线攻击额外命中个数 | 割草线 | 单体 |
| `aoeScale` | 范围缩放% | benefit | 扇形 / 地波范围 | 清怪面大 | 范围小 |
| `lifeSteal` | 吸血% | benefit | 造成伤害的 X% 转生命 | 越打越满 | 无吸血续航 |

**伤害结算（简化）**：

```
raw = attack × 武器系数 × (1 + attackSpeed影响射频，非单次伤害)
若暴击：raw × (1 + critDamage)
经过 target 护甲/减伤
heroHeal += raw × lifeSteal
```

## 6. 英雄 baseStats（② 层 — ① 的子集）

```typescript
HeroBaseStats {
  maxHp?, hpRegen?, lifeSteal?,
  attack?, attackSpeed?, critRate?, critDamage?, range?, pierce?, aoeScale?,
  armor?, dodge?, damageReduction?,
  moveSpeed?, pickupRange?,
  luck?, wealth?, goldGain?
  // ❌ 禁止：captureRate, digRare, petDamage, enhanceSuccess …
}
```

| 英雄流派 | 典型 base 偏高 | 典型 base 偏低/为 0 |
|----------|----------------|---------------------|
| 坦克 | maxHp, armor | attack, luck |
| 输出 | attack, critRate | maxHp, wealth |
| 抓宠 | luck 或 **attack** 偏高（二选一偏科） | 另一条 combat 线 |
| 挖宝 | luck/wealth 或 attack | 战斗弱有代价 |
| 赌狗 | luck, wealth | armor, maxHp |

**可为负吗？**  
- `baseStats` **建议不用负值**；用「低数值」表达短板  
- 道具 / 诅咒 / 附魔 **可以** 给负 modifier（如 `attack -10%`）

---

## 7. 正负 modifier 在配置里怎么写

```json
{
  "statId": "moveSpeed",
  "type": "percent",
  "value": 0.08,
  "sourceId": "item:heavy_gait:conditional"
}
```

| 场景 | 示例 | 效果 |
|------|------|------|
| 道具叠层 | `attack +5%/层` | 越多层越高攻 |
| 诅咒道具 | `attack +10%`, `auctionSnatchRate +3%` | 一正一风险 |
| 附魔词条 | `critRate +8%` | 装备 build |
| 局内 4 选 1 | `maxHp +80 flat` | 本局成长 |
| 赌狗流 | `luck +10`, `attack +5%` | 商店靠运，赌场减 debuff 靠攻 |

## 9. 局内 4 选 1 可出现属性（AttributePick）

与 StatId 对齐；**战斗与幸运财富同池竞争**：

| 档位 | 可出现 StatId |
|------|----------------|
| 普通 | maxHp, attack, armor, attackSpeed, critRate, **critDamage**, moveSpeed, luck, wealth |
| 稀有 | lifeSteal, hpRegen, dodge, range, pierce, aoeScale, goldGain |
| 传说 | 大额 attack/maxHp/armor，luck/wealth 跳档，maxPetDeploy（抓宠 build） |

各英雄 `attributePoolId` 只调 **权重**，不引入专用 StatId。

## 10. 附魔词条可出现 StatId

| 允许 | 例 |
|------|-----|
| ✅ 常见 | attack, critRate, maxHp, armor, **luck**, **wealth** |
| ✅ 养成 | enhanceSuccess, enchantRareWeight |
| ⚠ 成对 | +enhanceSuccess 与 +enhanceBreakRisk 不共存一条 |
| ❌ 避免 | captureRate, digRare；单条 `auctionSnatchRate +20%` 无补偿 |
